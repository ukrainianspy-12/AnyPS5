# libkernel

## change [rfork_thread and sceKernelRdup]

- [rfork_thread and sceKernelRdup](../../../core/libs/prx/libkernel/Unimplemented.cpp) (libkernel) - `sceKernelRdup` duplicates through `dup_nid_postfix` for the caller's pid and throws for other pids. `rfork_thread` now implements the shared-address-space case: flags containing `RFPROC|RFMEM` create a detached host thread on the supplied top-aligned stack, run the callback there, and return the host thread id as a positive child identifier; ProsperoWeb's published call site (NID `bSDxEpGzmUE`, `native_fork_probe.c`) establishes the signature and shared-memory use. On Windows the stack extent is read from the host region containing the supplied top; other hosts throw. Flags that copy the address space (`RFPROC` without `RFMEM`), a null stack or callback, and a stack that is not the top of one host region throw through `NotImplemented_nid_no_patch(__func__)`. The returned id is a host thread id, not a console process id: `waitpid` and sibling-process semantics are not provided, the callback returns to the host thread instead of calling `_exit`, and clean-fd flags are not applied. A guest runs as the only process here, so these gaps are not console measurements.
