# libkernel

## change [rfork_thread and sceKernelRdup]

- [rfork_thread and sceKernelRdup](../../../core/libs/prx/libkernel/Unimplemented.cpp) (libkernel) - `rfork_thread` throws. ProsperoWeb (PRWB00001) 0.2.1 imports both from `libkernel`. It declares `int sceKernelRdup(int pid, int fd)` and calls it with its own pid only after `dup` is refused with `EPERM` and `dup2` onto a reserved number fails ([`native_trace.c`](https://github.com/kvaps/ProsperoWeb/blob/8cfe29c3cbd763c8c832f414f902b68b7d9a09bb/src/frontend/ps5/native/native_trace.c#L157-L188)), and calls FreeBSD's `pid_t rfork_thread(int flags, void *stack, int (*func)(void *), void *arg)` only from a start-up fork probe that is off by default ([`native_fork_probe.c`](https://github.com/kvaps/ProsperoWeb/blob/8cfe29c3cbd763c8c832f414f902b68b7d9a09bb/src/frontend/ps5/native/native_fork_probe.c#L1-L40)). `sceKernelRdup` now duplicates through `dup_nid_postfix` when `pid` is the caller's, from the title's published call site; the console's own return convention is unmeasured. Any other pid throws through `NotImplemented_nid_no_patch(__func__)`, as does `rfork_thread`, since a guest runs as the only process here and no other process is available to duplicate a descriptor from or start.
